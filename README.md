# FaithLM: Towards Faithful Explanations for Large Language Models

This repository contains the refactored FaithLM framework, designed to evaluate the fidelity of explanations generated by Large Language Models.

## The two model roles

FaithLM needs **two** models, and they do different jobs. Getting this backwards is the most common source of confusion:

| Role | Flag | What it does |
|---|---|---|
| **Predictor** (a.k.a. *target model*) | `--pred_model` | The model under study. It answers the question, then answers it **again** with the explanation and with the counterfactual explanation. The gap between those two is the faithfulness score. Must answer **concisely** — scoring only reads a short continuation. |
| **Explainer** (XAI model) | `--xai_model` | Generates the explanation, generates the counterfactual explanation, and acts as the **LLM optimiser** that rewrites the explanation from the score history. |

## Run it in the browser (Colab / Kaggle)

[`notebooks/FaithLM_XCOPA_vi.ipynb`](notebooks/FaithLM_XCOPA_vi.ipynb) walks
through the whole project in eight sections — install, data, exploration,
models, evaluation, a baseline comparison, error analysis, and a live demo on
new Vietnamese sentences. It clones this repository itself and uses no local
paths.

[![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/lklong1551019/NLP_Final/blob/main/notebooks/FaithLM_XCOPA_vi.ipynb)

- **Without an API key** it still runs sections 1–3, 5a and 7: full-scale
  tables rebuilt from the 1,560+ committed results and the error analysis.
- **With a key** (any OpenAI-compatible endpoint, set as Colab Secret
  `LITELLM_API_KEY`) it also runs the live pipeline, the baseline comparison and
  the demo. Set `PRED_MODEL = "phi"` on a T4 runtime to use the paper's own
  target model locally.

The notebook is generated from `scripts/build_notebook.py`; edit that and re-run
it rather than editing the `.ipynb` by hand.

## Quick Start

### 1. Environment

```bash
# with uv (no CUDA needed if you run both roles through an API gateway)
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python \
    torch transformers datasets openai scikit-learn python-dotenv tqdm anthropic accelerate
```

or with conda:

```bash
conda create -n nlp_final python=3.12
conda activate nlp_final
pip install -r requirements.txt
```

> 4-bit quantization (`bitsandbytes`) requires CUDA. On Apple Silicon or any
> machine without an NVIDIA GPU, use the API-served predictor described below.

### 2. Configure `.env`

Create a `.env` in the repository root. Do **not** commit it.

**Option A — everything through an OpenAI-compatible gateway (LiteLLM, vLLM, …):**

```env
LITELLM_API_KEY="sk-..."
LITELLM_BASE_URL="https://your-gateway/v1"
LITELLM_PRED_MODEL="deepseek/deepseek-v4-flash"    # Predictor
LITELLM_XAI_MODEL="deepseek/deepseek-v4-pro"       # Explainer
LITELLM_FALLBACK_MODEL="openrouter/deepseek/deepseek-v3.2"
```

`LITELLM_FALLBACK_MODEL` is used when the primary returns an empty completion —
some providers do this instead of erroring when a content filter fires.

**Option B — local Predictor + API Explainer (the paper's setup, needs a GPU):**

```env
DEEPSEEK_API_KEY="sk-..."
DEEPSEEK_BASE_URL="https://api.deepseek.com"
DEEPSEEK_MODEL="deepseek-chat"
```

Model ids must be written exactly as the gateway exposes them, including any
provider prefix (`deepseek/deepseek-v4-pro`, not `deepseek-v4-pro`).

### 3. Run

**Single variant (local + global):**

```bash
bash scripts/run_experiment.sh [DATASET] [PRED_MODEL] [XAI_MODEL]

# API-served predictor and explainer:
PYTHON=.venv/bin/python bash scripts/run_experiment.sh copa_en litellm litellm

# Paper's setup, local Qwen predictor:
bash scripts/run_experiment.sh xcopa_vi qwen deepseek
```

**Parallel run (much faster).** The local pipeline treats each question
independently and writes one file per question, so it shards safely by question
index:

```bash
# DATASET PRED XAI START END ITER NSHARDS OUTDIR
bash scripts/run_sharded.sh copa_en litellm litellm 0 100 8 12 ./results/experiments/copa_en
```

**Full reproduction (English COPA, then Vietnamese XCOPA):**

```bash
N_QUES=100 ITER=8 NSHARDS=12 bash scripts/run_paper_repro.sh
```

### 4. Build the report

```bash
.venv/bin/python scripts/build_report.py \
    --results_dir ./experiments/<member> \
    --output ./experiments/<member>/SUMMARY.md
```

### Datasets

| `--data` | Source | Notes |
|---|---|---|
| `copa_en` | `pkavumba/balanced-copa` | English COPA — the paper's setup |
| `xcopa_vi` | `cambridgeltl/xcopa` (`vi`) | Vietnamese, human-translated. 500 test items |
| `ecqa` | `yangdong/ecqa` | Has human-written gold explanations |
| `copa`, `social`, `trivaqa` | various | Upstream branches, not exercised by our runs |

### Debugging

`FAITHLM_DEBUG=1` prints every raw predictor response before parsing — the
fastest way to see why an answer scored the way it did.

```bash
FAITHLM_DEBUG=1 .venv/bin/python main_local.py --data copa_en \
    --pred_model litellm --xai_model litellm --ques_idx_start 0 --ques_idx_end 3
```

**Where do results go?** Working runs land in `results/` (git-ignored). Results
that back a claim are moved to `experiments/<member>/<run>/` and committed — one
JSON per question for the local pipeline plus one for the global pipeline.

## Deliverables

| Item | Where |
|---|---|
| Report (ACL format) | [`paper/main.pdf`](paper/main.pdf) — source in `paper/main.tex`, build with `tectonic -X compile paper/main.tex` |
| Colab / Kaggle notebook | [`notebooks/FaithLM_XCOPA_vi.ipynb`](notebooks/FaithLM_XCOPA_vi.ipynb) |
| Experiment outputs | [`experiments/`](experiments/) — one folder per member; every number in the paper traces to a run there ([`paper/README.md`](paper/README.md)) |
| Datasets | `pkavumba/balanced-copa` and `cambridgeltl/xcopa` (`vi`) on the Hugging Face Hub; downloaded on first use |
| Trained model | **None.** This project evaluates and audits FaithLM; no model is fine-tuned. Targets are off-the-shelf (`microsoft/phi-2`, `Qwen/Qwen3.5-4B`) and explainers are API models. |
